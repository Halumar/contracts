# Codegen

Generates the contract models for every consumer from `schemas/**/*.json` (JSON Schema 2020-12) and
`namespace.json`:

| `--lang` | Consumer | Output | Content |
|---|---|---|---|
| `python` | hub (Home Assistant app), Home Assistant integration | package `hub_contracts/` (change with `--package`) | pydantic v2 models, `parse_*` for unions, `contract_errors()`, registry |
| `ts` | admin UI | `index.ts`, `namespace.ts` | types only (interfaces, literal unions), no runtime |
| `swift` | Apple apps | `Contract*.swift`, `Namespace.swift` | `Codable`/`Sendable`/`Hashable` structs, enums with `.unknown(String)`, `validate()` |
| `kotlin` | Android apps | `<package>/*.kt` (`--package`, default `hubcontracts`) | kotlinx.serialization data classes, sealed interfaces for unions, `validate()` |

```sh
python3 tools/codegen/generate.py --lang swift --out <dir>            # write
python3 tools/codegen/generate.py --lang swift --out <dir> --check    # compare, exit 1 on drift
```

`generate.py` needs only the Python standard library (3.11 or later). The output is deterministic (no
time stamps, sorted); the header of every file names the contract version and a SHA-256 over
`schemas/` and `namespace.json`. The output directory belongs to the generator: files with the marker
`Generated by contracts/tools/codegen/generate.py - DO NOT EDIT.` that are no longer generated are
deleted (or reported with `--check`); other files are left alone.

**Contract data** (`data/<name>.json`, schema `schemas/data/<name>.json`) is also generated as a
constant: Python `hub_contracts/data.py` (`TILE_CAPABILITIES_JSON` and a cached loader
`tile_capabilities()`), TypeScript `data.ts` (`DATA_TILE_CAPABILITIES: DataTileCapabilities`), Swift
`ContractData.swift` (`ContractData.tileCapabilitiesJSON`, `try ContractData.tileCapabilities()`),
Kotlin `ContractData.kt`. The content is canonical (sorted keys) and part of the input hash.

## Why a custom generator

`datamodel-code-generator` (Python), `json-schema-to-typescript`, `quicktype` and `@asyncapi/modelina`
were evaluated. The decision: **one small custom generator** (`hubgen/`, about 2,300 lines of Python, plus
about 800 lines of hand-written runtime for Python, Swift and Kotlin) with an intermediate
representation (IR) and four emitters.

- **One behavior in four languages.** Tolerance for unknown enum values (`.unknown(String)`), unknown
  message types, `boolish`, two shapes per `type`, namespace constants and `validate()` must work the
  same everywhere. With four external tools that would mean four post-processing scripts; quicktype and
  Modelina generate strict enums without a fallback for Swift and Kotlin.
- **Determinism without version drift.** The output depends only on this repository, not on npm or pip
  versions. That is what makes `--check` in the consumer CIs possible.
- **Fail loud.** The contract uses a small subset of JSON Schema (below). Any other keyword stops the
  generation with `SchemaError` (exit 2) instead of being ignored.
- **No runtime dependencies** except pydantic (Python, already present in the hub and in Home Assistant
  Core) and kotlinx.serialization (Android).

`datamodel-code-generator` would have been enough for Python alone, but knows neither the tolerant enum
semantics nor deviation D8 ([docs/protocol.md](../../docs/protocol.md#known-deviations)) and would have
been a second source for the same logic.

## Semantics: decode tolerantly, validate strictly

| | Decoding | `validate()` / `contract_errors()` |
|---|---|---|
| unknown fields | ignored (Python: kept in `model_extra`, encoded again) | Python: error with `additionalProperties: false` |
| unknown enum value | `.unknown("x")` / `Unknown("x")` / `str` | error |
| unknown `type`/`command` | `.unknown(JSONValue)` / `UnknownMessage` | – |
| wrong JSON type (for example `"8100"` instead of `8100`, known deviation D3) | **error** | – |
| integer overflow, fraction for an integer, `1e400` | **error**, never a trap or crash | non-finite numbers: error |
| `pattern`, `min/max*`, `const`, `format`, `dependentRequired`, `anyOf` required groups, `not: required`, `if/then/else` | – | error |

A client therefore stays forward compatible (new fields, enum values and messages break nothing), and
the hub can still check incoming messages completely (`parse_client_message(raw)` plus
`contract_errors()`). Wrong JSON types are a contract violation and fail loudly.

More rules:

- **Null versus missing.** Required fields with `null` in their type are declared non-optional but
  nullable (`String?` without a default) and are always encoded (also as `null`). Optional fields are
  left out when they are `nil`. Python distinguishes exactly (`to_dict()` = `exclude_unset`). Swift and
  Kotlin treat an optional `null` like "missing".
- **Discriminators** (`type`, `command`) are constants of the type (`ServerAuthOk.type`), checked when
  decoding and always written when encoding, also for messages built in code.
- **Patterns** are ECMA-262 (`search` semantics). A trailing `$` becomes `\Z`/`\z`, because Python, Java
  and ICU also match `$` before a trailing newline (`"1234-5678\n"` is not a PIN).
- **Swift**: `Int`/`Double` with Foundation's `JSONDecoder` (throws on overflow; `JSONEncoder` throws on
  NaN/∞ with the default strategy `.throw`). No `Synchronization`, no `Span`, no regex literals (iOS 17 /
  tvOS 17 / macOS 14); regex checks use `String.range(of:options: .regularExpression)`. Swift 6 language
  mode.
- **Kotlin**: use `ContractJson` (`ignoreUnknownKeys`, `encodeDefaults = false`, `explicitNulls = true`).
  kotlinx otherwise accepts `"80"` for `Long` and `"true"` for `Boolean` even without `isLenient`; the
  generated models therefore use `StrictLong`/`StrictDouble`/`StrictBoolean`.
- **Kotlin identifiers and comments**: enum cases are nested objects of the sealed class and would hide
  types of the same name there (`object String` turns every `String` in the class into the case). Cases
  named like a type of the default imports (`kotlin.*`, `kotlin.collections.*`, for example `String`,
  `Boolean`, `List`, `Pair`, `Error`), like a name used in the enum body (`Serializer`, `Companion`,
  `Unknown`, …) or like the enum itself get the suffix `Value` (`"string"` → `StringValue`, `"list"` →
  `ListValue`, `"unknown"` → `UnknownValue`); list `KOTLIN_RESERVED_CASES` in `hubgen/emit_kotlin.py`.
  Backticks do not help (`` `String` `` is the same name). If two values give the same case, generation
  stops (`SchemaError`). Kotlin nests block comments: in KDoc `/*` becomes `/&#42;` and `*/` becomes
  `*&#47;` (descriptions like `schemas/ws/server/*`).
- **Sensitive fields** (`x-sensitive`): Python `repr=False`, Swift `customMirror` and Kotlin
  `toString()` do not print the value.
- **Namespace**: only the namespace file (`namespace.py`, `namespace.ts`, `Namespace.swift`,
  `Namespace.kt`) contains values from `namespace.json`. Models refer to constants, also in patterns and
  JSON keys (`<ns>_area_id` → property `areaSwitchIdAttribute`). Descriptions replace the literal with
  `<ns>`. The file names match `namespace_allowed` of the brand lint (`.brandlint.toml`).

## Mapping

| JSON Schema | Python | TypeScript | Swift | Kotlin |
|---|---|---|---|---|
| `string` | `StrictStr` | `string` | `String` | `String` |
| `integer` | `StrictInt` | `number` | `Int` | `StrictLong` (`Long`) |
| `number` | `Number` (strict float) | `number` | `Double` | `StrictDouble` |
| `boolean` | `StrictBool` | `boolean` | `Bool` | `StrictBoolean` |
| `$defs/boolish` | `Boolish` (`bool \| 0 \| 1`) | `Boolish` | `Boolish` (keeps the wire form) | `Boolish` |
| string `enum` | `StrEnum` + `…Value` (`Enum \| str`) | literal union + `…_VALUES` | `enum … { case …, unknown(String) }` | `sealed class … { object …, Unknown }` |
| object with `properties` | `ContractModel` | `interface` | `struct` | `data class` |
| free object / no type | `dict[str, Any]` / `Any` | `Record<string, unknown>` / `unknown` | `[String: JSONValue]` / `JSONValue` | `JsonObject` / `JsonElement` |
| `anyOf` of `$ref`s with `type` (unions) | `Union[…]` + `parse_*()` | union type | `enum` with associated values | `sealed interface` + serializer |
| `anyOf` of inline objects (for example `notify.response`) | as above, without unknown | union | `enum` | `sealed interface` |
| `allOf: [$ref]` | fields inherited (flat) | flat | flat | flat |
| `not: {required: [x]}` | check | `x?: never` | check | check |

Type names follow the path (`ws/server/auth_ok.json` → `ServerAuthOk`, inline objects
`IntegrationStatusResponseHub`, array items `…Item`, `$defs` → the def name). Prefixes are in
`hubgen/ir.py` (`DIR_PREFIX`); new directories get the PascalCase path without `ws` (`ws/integration` →
`Integration…`); name collisions stop the generation.

Supported subset: `type` (also `[T, "null"]`), `properties`, `required`, `additionalProperties` (bool or
string schema), `$ref` (local and relative), `allOf` (`$ref`, or `if/then/else` with a `const`/`enum`
condition on one property, optionally `required`; `then`/`else` with `required`, `not: {required}`,
`properties` as `const` or the non-null form of the property), `unevaluatedProperties` (bool, same
meaning as `additionalProperties` because models are flat over `allOf`), `anyOf` (nullable, string
alternatives, required groups, unions), `enum`, `const`, `not: {required}`, `dependentRequired`,
`pattern`, `minLength`, `maxLength`, `format` (`date-time`, `ipv4`), `minimum`, `maximum`, `minItems`,
`maxItems`, `uniqueItems` (only string, enum and integer lists), `maxProperties`, annotations and `x-*`.
`default` is not applied (missing stays missing).

## Using it in a consumer

The consumer pins a contract tag (`.github/contracts-ref`) and checks in the generated files:

```make
contracts:   ## generate the models again
	python3 contracts/tools/codegen/generate.py --lang python --out $(APP_DIR)
contracts-check:
	python3 contracts/tools/codegen/generate.py --lang python --out $(APP_DIR) --check
```

| Consumer | Call |
|---|---|
| hub | `--lang python --out <app-dir>` (package `hub_contracts/`), `--lang ts --out frontend/src/lib/contracts` |
| integration | `--lang python --out custom_components/<domain> --package contracts` |
| Apple apps | `--lang swift --out <models directory of the app>` |
| Android apps | `--lang kotlin --out <source directory of the app> --package <package of the app>` |

The consumer's CI runs `--check` and tests against `contracts/fixtures` (Python:
`hub_contracts.parse(schema_path, data)`; Swift: `ContractSchemaRegistry.decode(_:from:)`; Kotlin:
`ContractSchemaRegistry.serializerFor(path)`).

## Tests

```sh
python3.12 -m venv .venv
.venv/bin/pip install -r tools/codegen/requirements.txt
.venv/bin/python tools/codegen/tests/test_codegen.py -v
```

- **Generator**: deterministic; `snapshots/<lang>` match the generation (snapshot test = `--check`);
  `--check` detects changes and stale files; the namespace literal appears only in the namespace files;
  unknown keywords stop the generation.
- **Round trip over all golden fixtures** in Python, Swift and Kotlin: decode → `validate()` empty →
  encode → equal to the fixture (Python exactly, Swift and Kotlin against the projection without unknown
  fields and optional `null`) → the result validates against the JSON Schema. WebSocket fixtures also go
  through the union (`ClientMessage`/`ServerMessage`), which must pick the expected type. Every
  `invalid-*` fixture must fail when decoding or in `validate()` (see Limits for the exceptions in Swift
  and Kotlin).
- **Swift** (`swift test`, Swift Testing; the package `tests/swift` is copied into a temporary
  directory) also covers: unknown enums and types, integer overflow, NaN/∞, type errors, `boolish`,
  required `null`, redaction of sensitive fields.
- **Kotlin** (Gradle project `kotlin-check/`: Kotlin Gradle plugin 2.4.21, kotlinx.serialization 1.13.0,
  toolchain JDK 21, API JDK 17, `-Werror`): compiles `snapshots/kotlin` together with
  `tests/kotlin/RoundTrip.kt` and runs the round trip with the same self tests (task `roundTrip`). Build
  output goes to a temporary directory (`-PbuildRoot`, `--project-cache-dir`). Needs `gradle` on the
  `PATH` or `GRADLE` (path to `gradle` or a `gradlew`) and a JDK 21, otherwise skipped
  (`CODEGEN_SKIP_KOTLIN=1` skips it explicitly). Generator tests without a toolchain also check that no
  KDoc contains `/*` and no enum case hides a type.
- **TypeScript** (`tsc --strict --exactOptionalPropertyTypes`, through `npx` or `TSC`): every valid
  fixture is assignable to the generated type and to the union; three `@ts-expect-error` cases
  (`CODEGEN_SKIP_TS=1` skips it).
- `CODEGEN_SKIP_SWIFT=1` skips Swift. `CODEGEN_REQUIRE_ALL=1` (CI) turns skipped languages into
  errors. CI: `.github/workflows/validate.yml`, jobs `codegen-check` (snapshots of all four languages,
  Python, Kotlin and TypeScript round trips; Gradle 9.9.1 from the runner's tool cache, checksum
  checked) and `codegen-swift` (Swift round trip).

**After every schema change**: run `generate.py` for all four languages into
`tools/codegen/snapshots/<python|typescript|swift|kotlin>` and commit the diffs. `tools/validate.py`
leaves the snapshots out of the namespace check, because they are generated from `namespace.json` and
kept current by `--check`.

The snapshots (about 5 MB: Swift 2.1 MB, Kotlin 1.4 MB, Python 1.0 MB, TypeScript 0.7 MB) are checked
in on purpose: `--check` and the round-trip tests compare against them, and a consumer can see the
models of a contract version without running the generator.

## Limits

- Swift and Kotlin cannot check `additionalProperties`/`unevaluatedProperties: false` and
  `maxProperties` on typed objects (unknown fields are dropped when decoding); Python can. The test lets
  `invalid-*` fixtures whose only fault is that pass in Swift and Kotlin.
- Swift and Kotlin do not distinguish `null` and missing for optional fields; `dependentRequired` and
  similar treat "present" as "not null".
- Semantic checks of `tools/validate.py` (deep link URI ↔ parameters, crypto vectors) are not generated;
  the crypto vectors have models (`CryptoComplianceVectors`, `CryptoSettingsPinVectors`), recomputing
  them belongs in the consumer tests.
- Time stamps stay strings (known deviation D6: mixed formats); `format: date-time` is checked only where the
  schema asks for it (`utc_expiry`).
- REST answers without a schema (`x-todo` in OpenAPI) have no models yet; once they are under `schemas/`
  they are generated too.
